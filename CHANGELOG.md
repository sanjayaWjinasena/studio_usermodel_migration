>
> v0.53 shipped 2 stored fields on base.automation as inherit-fields.
> That crashed the Dev server on restart with:
>   ERROR: column base_automation.x_studio_comments does not exist
> Root cause: Odoo's base_automation._register_hook runs a SELECT of
> every stored column at registry init. On a code-pull (git pull) WITHOUT
> running `-u studio_usermodel_migration`, the Python class picks up the
> new field definitions but the DB ALTER TABLE hasn't executed, so the
> hook query references columns that don't exist. Crashes every server
> restart until the code is reverted or the columns are created.
> Emergency fix: drop the 2 fields entirely. Server can restart, then
> we can plan a safer port path (data-XML ir.model.fields insert that
> runs BEFORE the Python model class registers, or non-stored compute).
> Ports for ir.model.access + ir.rule (v0.53 same commit) are unaffected
> — those models don't have a _register_hook that queries all columns.
